# 智能调度考察期

## Goal

智能调度配对在冷却到期后进入 **考察 `probing`**：夹 in-flight 并发、用配对质量 \(Q_{a,u}\) 评价，达标再进调度。原则：**越灵活越好，避免状态死锁**。管理员可随时手选暂停 / 冷却 / 考察 / 调度 / 豁免期。自动链只有 **冷却到期 → 考察 → 调度**；豁免期是 **仅手动** 的快路径，期满进调度、不经考察。

**暂停 `paused` 是长期手选态**：管理员故意切入，并长期停在那里。**不存在「暂停解除」自动链**，也没有默认下一态。离开暂停必须再手选 考察 / 调度 / 豁免期 / 冷却。禁止写成「取消暂停 → 默认考察」。

本任务 **新建**，不复用、不改写 `.trellis/tasks/08-21-smart-schedule-recovery-probe`（配对 last-N 冷却已交付）。账号质量 last-N / 硬关闭是另一条进行中任务，本任务不得改那条轨。

## Background

配对冷却已按 \(Q_{a,u}\)（账号×用户、最近 N 条双窗）工作。冷却到期后现网直接当可调度：`expirePairCooldown` `HDEL` + 两窗清零，下一次 `admitsScheduleUser` 按池成员原 cap 准入。没有中间态夹并发。

现网入池可写状态只有 `paused` / `cooling` / `resumed` / `selectable`。`paused` 是管理员手选的长期跳过，不是会自动翻面的临时锁。`resumed`（界面「豁免期」）是时间豁免（`u:` 15m + `w:` 至 30m），期内入窗不判断，期满再判断；**不是**限并发考察。

本任务补上真正的考察态，并冻结与豁免期 / 可调度的分流。2026-08-21 用户拍板 Q2–Q4；**Q1 经用户更正**（无暂停自动解除）。开放问题已关闭。

## Requirements

### 状态（界面中文 / API 英文）

| 界面 | API | 谁能进入 | 准入 | 入窗 | 评价 \(Q_{a,u}\) |
| --- | --- | --- | --- | --- | --- |
| 暂停 | `paused` | **仅手动进入；仅手动离开**（长期保持） | 跳过 | 无 | 无 |
| 冷却 | `cooling` | 越界自动，或手动 | 跳过 | 无 | 无 |
| 考察 | `probing` | 冷却到期自动，也可手动（含从调度拉回） | 夹并发 | 有 | 有 |
| 调度 | `selectable` | 考察毕业自动，也可手动跳过 | 成员原 cap | 有 | 有（无时间豁免） |
| 豁免期 | `resumed` | **仅手动** | 成员原 cap | 有 | 宽限内无；期满后有 |

API / 代码名保持上表英文。界面中文用「考察」「调度」「豁免期」。不发明第六态。不发明「解除暂停」中间态。

### 自动链 vs 手动

- **唯一自动链**：冷却到期 → 考察 → 调度。自动到期 **只** 进考察，不进调度、不进豁免期。
- **手动快路径**：豁免期 →（宽限期满）→ 调度。不经考察。
- **暂停无自动出口**：没有 implicit unpause，没有默认目的地。离开 = 管理员显式点下一态（考察 / 调度 / 豁免期 / 冷却），再走该态副作用。
- **清 `paused` 旗标不得暗进 `probing`。**
- **调度→考察**：允许手选拉回。不经冷却、两窗清零、并发改夹紧。不写宽限。

### 考察并发

- 与配对窗同一个策略 N（默认 10，1–100）。
- 成员已设配对 cap：`min(N, cap)`。
- 未设 cap：就是 N（不是无限，也不是 UI 999）。
- 只限 **in-flight** 配对槽，不是样本条数、不是账号总并发。

### 进入考察（冷却到期，或管理员手选——含从调度拉回）

- 清冷却。
- **两窗清零**。
- **不写** `u:` / `w:` 宽限。
- 并发改夹紧（上表考察 cap）。

从调度拉回考察 **不经冷却**，只夹并发；副作用与上表相同。从暂停进入考察也必须是这次手选「考察」，不是解除暂停的默认。

### 考察 → 调度（毕业）

- **保留** 考察期攒下的两窗。
- 必须 \(W_{ok}\) 已满 N。
- 若配置了成功率门槛，成功率须在门槛内。
- \(W_{ttft}\) 空 / 未满（含同步-only、无首字）**不挡** 毕业。
- 若 \(W_{ttft}\) 已满，p50 必须过（否则回冷却，不是毕业）。
- **没有** 按时间毕业。无流量时不毕业，留在考察等待。

### 考察 → 冷却

- 与现网配对冷却同一套 or/and，未满的指标不参加。
- **考察专则（Q2）**：`and` 且两窗都满、一好一坏（标准 `and` 不回冷、毕业也不成立）→ **回冷却**，不得夹着空转。
- 此专则 **只作用于考察**。调度态仍要两窗都越界才按 `and` 冷却。

### 手动调度

- 清冷却；**两窗清零**；不写 `w:`；成员原 cap（无 cap 则不夹）。
- 清考察标记。

### 手动豁免期

- 清冷却；**两窗清零**；现网时间宽限（`u:` 15m + `w:` 至 30m）；成员原 cap。
- 清考察标记。
- 宽限内入窗、不判断。
- 宽限期满 → 调度，**保留** 宽限期内窗口，然后再评价。不进考察。

### 上线不回填（Q4）

- 已在调度（无冷却、无暂停、无考察标记）的配对维持调度、原 cap。
- 只有 **新的** 冷却墙钟到期，或 **新手选考察**，才进入考察。
- Redis miss / 无考察标记 = 非考察。禁止部署后扫描回填。

### 反死锁 / 灵活跳转

- 管理员可随时跳到：暂停 / 冷却 / 考察 / 调度 / 豁免期。切换器五态都可选，不因当前态禁用「考察」。
- 自动冷却到期 → **只** 进考察。
- 同步-only / \(W_{ttft}\) 空或未满 **永不** 挡毕业（前提 \(W_{ok}\) 已满 N，且已配成功率门槛则须过）。
- 考察 `and` 两窗满、一好一坏 → 冷却。
- 考察期无流量 = **留下等待**，不发明等待态；管理员可强制调度或豁免期。
- 无按时间毕业。
- 不发明额外状态（无 `stuck` / `probe_waiting` / `probe_mixed` / `unpause`）。
- 从暂停切走必须再点下一态；切换器不得暗默认 `probing` 或 `selectable`。

### 硬约束

- 不发明同步假 TTFT。
- 不改客户端协议（不得要求改 `stream` / 端点 / body）。
- 不改账号质量 last-N / 硬关闭（独立进行中任务）。
- 配对冷却仍只读 \(Q_{a,u}\)。
