# user_id=16 展示层 token 分布（只读）

## 窗口与方法

- 生产只读：`root@172.245.247.80` / `sub2api-postgres`。无写入。
- 用户：email 仅用于解析 → **user_id=16**，`downstream_usage_token_mode=display`，无用户级 M 覆盖。
- **窗口：近 7 天**（查询时 `NOW()≈2026-08-24 00:00+08`）→ **n=322175**。14 天全量 605570 行未再跑重 CTE（7 天已覆盖要求的 7–14 天窗口）。
- 落库 `usage_logs.*_tokens` 是 **计费实数**，不是展示值。本文件主表是 **读时 L1+L2 近似**。

### 展示回算

与现网配置对齐，不是 raw SQL 列：

- 用户展示价覆盖（优先于 global）：  
  `gpt-5.4` 2.5e-6 / 1.5e-5 / 2.5e-7；`gpt-5.5` 5e-6 / 3e-5 / 5e-7；  
  `gpt-5.6-sol` 4e-6 / 2e-5 / 4e-7；`gpt-5.6-terra` 2e-6 / 1.2e-5 / 2e-7。
- 长上下文行：展示价先乘 snapshot 乘数（与 `EffectiveDisplayPricingForUsageLog` 相同）。
- L1：`round(component_cost / P_display)`；cache 再 `min(., real×1.4)`（现网 M=1.4）。
- L2：`scale = rate_multiplier / 0.14`（分组 19 展示倍率 0.14；本用户 7 天流量均在 19）。cache 再夹到 `real×M`。
- **未建模** L1 cache 残差折入 output/input（α=2.5）。对 sol/terra/5.5（展示价≈计费价）误差小；gpt-5.4（展示价约一半）会 **略低估** display input。gpt-5.4 仅 12694/322175（3.9%）。

计费实数分位数（14 天，先前查询）只作对照，**不能**当 cap 依据。
